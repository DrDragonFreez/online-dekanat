# Положение о предварительной проверке студенческих документов
Версия 1.0. Учебный университет «Меридиан».

Это вымышленные правила для кейса «Онлайн-деканат». Они не описывают требования реального вуза и не являются нормативным актом. Все сведения в примерах созданы специально для хакатона. Совпадения с реальными людьми или организациями случайны.

## 1. Назначение и границы сервиса
1.1. Сервис помогает студенту прочитать документ, получить его поля и предварительно проверить наличие обязательных сведений.
1.2. Основной сценарий: студент загружает один документ и задаёт вопрос на русском языке. Тип документа можно выбрать вручную. Поддерживаются справка об обучении, заявление на академический отпуск и справка о практике.
1.3. Окончательное решение о принятии документа и удовлетворении заявления принимает сотрудник деканата. Сервис не сообщает «документ принят», не оформляет перевод, отпуск или зачёт практики.
1.4. В обязательную версию не входят кабинет сотрудника, передача обращения в настоящий деканат, переписка, уведомления и отслеживание статуса. Новый тип документа через конфиг и подсветка найденных полей являются дополнительными возможностями.

## 2. Общие правила чтения и ответа
2.1. Источниками ответа служат только загруженный документ и настоящее Положение. Ответ должен обозначать используемые поля документа и/или конкретные пункты Положения.
2.2. Если текстовое поле отсутствует или его значение нельзя прочитать, сервис указывает «не найдено». Нельзя дополнять ФИО, даты, номера и другие значения предположениями. В выданных наборах текст читаем, поэтому «не найдено» означает незаполненное поле.
2.3. Для подписи и печати проверяется наличие соответствующего графического элемента. Напечатанная подпись к месту заполнения, например «Подпись» или «М.П.», сама по себе не подтверждает наличие подписи или печати. Подлинность подписи и печати не проверяется. В учебных документах эти элементы являются условными графическими макетами.
2.4. Когда ответ нельзя получить из документа и Положения, сервис сообщает об отсутствии информации и рекомендует обратиться в деканат. Нельзя подставлять реальные правила других вузов или сведения из памяти модели.
2.5. Даты при извлечении приводятся к формату ГГГГ-ММ-ДД. Для периодов отдельно извлекаются начало и окончание. Прочие текстовые значения сохраняются без изменения смысла. Правила нормализации для автопроверки описаны в README.
2.6. Для этого учебного набора проверка «документ в порядке» означает наличие всех полей и графических отметок, обязательных для выбранного типа. Проверка юридической силы, подлинности, сроков давности и права студента на перевод или отпуск в набор не входит. В заполненных датах и периодах нет намеренно противоречивых значений.

## 3. Справка об обучении
3.1. Обязательные текстовые поля: ФИО студента, название вуза, направление подготовки, форма обучения, начало и окончание периода обучения, номер справки, дата выдачи.
3.2. Обязательна подпись уполномоченного сотрудника вуза.
3.3. Обязательна печать вуза.
3.4. При отсутствии любого элемента из пунктов 3.1-3.3 сервис перечисляет недостающие поля и указывает соответствующие пункты. При наличии всех элементов сообщает, что справка содержит обязательные сведения. Для проверки достаточно одной страницы справки.
3.5. Наличие справки не позволяет определить курс перевода, перезачёт дисциплин или число академических задолженностей. Эти условия настоящим Положением не установлены.

## 4. Заявление на академический отпуск
4.1. Обязательные текстовые поля: ФИО студента, учебная группа, курс, причина отпуска, дата начала отпуска, дата окончания отпуска, дата заявления.
4.2. Обязательна подпись студента.
4.3. Печать вуза и подпись сотрудника деканата для предварительной проверки заявления не требуются. Поле печати в карточку этого типа не входит.
4.4. Для предварительной проверки достаточно указанной непустой причины отпуска. Подтверждающие документы, допустимость причины, максимальная длительность отпуска и сохранение выплат в данном кейсе не оцениваются и настоящим Положением не установлены.
4.5. При отсутствии любого элемента из пунктов 4.1-4.2 сервис перечисляет недостающие поля и соответствующие пункты. При наличии всех элементов сообщает, что заявление содержит обязательные сведения.

## 5. Справка о практике
5.1. Обязательные текстовые поля: ФИО студента, название организации, дата начала практики, дата окончания практики, ФИО руководителя практики, оценка, номер справки, дата выдачи.
5.2. Обязательна подпись руководителя практики.
5.3. Обязательна печать организации.
5.4. При отсутствии любого элемента из пунктов 5.1-5.3 сервис перечисляет недостающие поля и соответствующие пункты. При наличии всех элементов сообщает, что справка содержит обязательные сведения.
5.5. Конкретная оценка читается из документа. Порядок выставления оценки, зачёта практики и требования к содержанию отчёта настоящим Положением не установлены.

## 6. Формулировки результатов
6.1. Если обязательные сведения присутствуют, сервис сообщает: «Документ содержит все обязательные сведения по пунктам ... Положения. Окончательное решение примет сотрудник деканата». Это результат предварительной проверки.
6.2. Если обязательных сведений не хватает, сервис перечисляет их и указывает пункты, которые требуют эти сведения. Отсутствие одного поля не мешает извлечь остальные.
6.3. Если источники не содержат ответа на вопрос, сервис сообщает: «В документе и в Положении нет информации для ответа на этот вопрос. Обратитесь в деканат».
6.4. Примеры 6.1-6.3 не ограничивают фактические вопросы. На вопрос «Какова дата выдачи?» сервис возвращает найденную дату и ссылку на поле. Вопросы о координатах из вспомогательного OCR-бенчмарка не являются обязательными пользовательскими вопросами кейса.
6.5. Самостоятельная проверка без вопроса может быть реализована отдельной кнопкой, которая задаёт стандартный вопрос «Содержит ли документ все обязательные сведения?». Отдельный режим без вопроса не обязателен.
